## Self-containment check

Every string in all 82 entries (pre-halt) was scanned for file-like references (61 distinct). Result:
**the chain is self-contained in substance, with three classes of exception, none fatal.**

### (a) Two references outside the migrated tree — resolvable

| Reference | Resolves to |
|---|---|
| `qhf/data/csv_loader.py` | the harness repo → **landed in `research.datasets`**, not `resources` |
| `quant_harness/examples/run_cnk_sweep_oos.py` | the harness repo → `research` examples |

Both point into `quant_harness`, which is itself being absorbed. They resolve through the
`PROJECT_RENAME` module-path mapping, which per the naming ruling must be a **mapping**, not a
single old→new namespace pair, since `qhf.*` fans out across four packages.

`CLAUDE.md` is referenced 7 times and lives at the WMPS repo root. It migrates at Phase 3.

### (b) Three referenced artifacts do not resolve at their recorded paths — **a second, unrecorded rename already happened**

| Recorded in log | Actually on disk |
|---|---|
| `research/artifacts/zlch_signal_edge_20260613T124557Z.json` | `research/pre/artifacts/…` |
| `research/artifacts/avwap_sweep_reclaim_signal_edge_20260614T083827Z.json` | `research/pre/artifacts/…` |
| `research/artifacts/avwap_multibar_reclaim_signal_edge_20260614T133418Z.json` | `research/pre/artifacts/…` |

All three files exist; only the recorded prefix is stale. The pre/post reorganisation moved
`research/artifacts/` → `research/{pre,post}/artifacts/` **without appending a path-migration
event**, so the log already contains unresolvable paths and no recorded means of resolving them.

This is exactly the failure the spec's `PROJECT_RENAME` mechanism exists to prevent, and it has
already occurred once, silently. **Recommendation:** the Phase 0.5 events must carry this
historical mapping too — not just the `qhf` → four-package mapping. A reader resolving a
seq<40 artifact path otherwise gets a file-not-found with no explanation.

### (c) `research/data/` is gitignored, and T9a's parity assertion depends on it

`ohlc_hash` in the seq=31 `flood_tide_h1` artifact is `_sha16(ohlc.to_csv())` over
`research/data/XAUUSD_H1.csv`. That file is untracked and gitignored.

**Verified this run:** loading it through the driver's `load_ohlcv()` reproduces

```
n_bars    124887
start     2004-06-11 07:00:00+00:00
end       2025-12-31 23:00:00+00:00
ohlc_hash a8cd64270c5376ca   ← matches the artifact exactly
```

So T9a assertion 1 passes today. But it passes by luck of an untracked file not having been
touched. Nothing prevents a re-pull from MT5 from silently changing it and turning a data
change into an apparent indicator regression — precisely the misattribution T9a's ordered
assertions are designed to prevent.

**Recommendation:** the T9a input CSV is committed as a test fixture (7.6 MB) under the
research package, or its hash is pinned in a tracked manifest with the file stored via LFS.
Either way it stops being gitignored before T9a is written.

## Migration sequence

`git subtree add` operates on whole repositories, so moving a subdirectory with history takes a
`split` first. Target layout per the naming ruling — distribution `qh-research`, imported
unprefixed as `research`:

```
quant_harness/packages/qh-research/research/
```

### Step 0 — commit the outstanding research tree  ← **DONE, merged to `origin/main`**

```bash
cd ~/Local/wine-mt5-python-setup
git add research/log/entries.jsonl research/log/log.md      # 53 appended entries
git commit -m "chore(research): commit log entries seq=30..82 incl LIVE_RISK_HALT"
git add research/pre research/post research/audit_seed_metrics.md
git commit -m "chore(research): track sweep engines and post-stage artifacts"
# decide research/data/ separately — see (c) above
```

Without this, `subtree split` carries three commits and 34 files.

### Step 1 — split `research/` into its own history

```bash
cd ~/Local/wine-mt5-python-setup
git subtree split --prefix=research -b research-only
# → branch 'research-only' whose root is research/'s contents
```

### Step 2 — graft it into the new repository

```bash
cd ~/Local/quant_harness
git remote add wmps ~/Local/wine-mt5-python-setup
git fetch wmps research-only
git subtree add --prefix=packages/qh-research/research wmps research-only
```

### Step 3 — verify the chain survived, byte-for-byte

```bash
cd ~/Local/quant_harness/packages/qh-research
python3 -c "
from research.log import verify, trial_count, _read_all, DEFAULT_LOG_DIR
ok,msg = verify(); e=_read_all(DEFAULT_LOG_DIR)
assert ok, msg
assert trial_count() == 26,          f'trial_count drift: {trial_count()}'
assert len(e) == 83,                 f'entry count drift: {len(e)}'
assert e[-1].entry_hash == '91470ef9fd2f9a97dc0d77006f36e85864bdaef531140fcdf40156faabf6050d'
print('D7 baseline reproduced after migration')"
```

### Step 4 — append the two migration events

`REPO_MIGRATION` then `PROJECT_RENAME`, in that order, per Phase 0.5 step 3.
`PROJECT_RENAME` carries the full module-path mapping **plus** the historical
`research/artifacts/` → `research/{pre,post}/artifacts/` mapping from finding (b).

### Step 5 — dry-run first

All of the above is rehearsed on a scratch clone (`git clone --no-hardlinks`) and the Step 3
assertions must pass there before the real run. Required by Phase 0 acceptance.

### Sequencing conflict to resolve

Phase 0 acceptance requires "D7 baseline recorded as a log entry of type `AUDIT`", while also
requiring "**zero changes to production code**". `research/log.py`'s `EventType` enum has no
`AUDIT` member, so satisfying the first breaks the second.

Three ways out, in preference order:

1. **Record the D7 baseline in the Phase 0 artifact JSON and memo now; append the `AUDIT`
   entry in Phase 0.5** alongside `REPO_MIGRATION`, once `log.py` is legitimately editable
   under T6. The baseline is preserved either way; only the ledger write is deferred.
2. Treat `EventType` extension as additive and outside the "production code" freeze — it is
   research infrastructure, not execution code, and `log.py` is explicitly a Phase 1 target.
3. Reuse an existing `EventType` with an `AUDIT` marker in the payload — rejected: it makes
   the entry type dishonest, which is the opposite of the log's purpose.

**Recommendation: option 1.** It keeps Phase 0's zero-code-change guarantee exactly true and
loses nothing, because the D7 numbers are already captured and independently reproducible.

### The one thing the dry-run surfaced

`research/data/` is gitignored, so it does **not** travel with the subtree. In the grafted
repo `python3 -m research.data_manifest` fails immediately with `no CSVs under …/research/data`.

first run in the new tree with an error that looks like a packaging fault rather than a
