# `research/` — Signal-Edge Research Framework

Pre-strategy evidence gathering for XAUUSD signals. This package is **upstream**
of `backend/trading/app/quant/strategies/` and must **never import from it**.
It decides whether an idea is worth building a strategy around, and records every
attempt so the multiple-testing tax stays honest.

## Layout

The module is split by **pipeline stage** — `pre/` (before a strategy/backtest
exists) and `post/` (after the harness has produced returns) — around a shared
**registry spine** (`log.py` + `seed_log.py` + `log/`) that both stages write to.

```
research/
├── log.py            ← SPINE: append-only, hash-chained research log + trial_count()
├── seed_log.py       ← SPINE: seeded hypothesis registrations (backfill, idempotent)
├── log/              ← SPINE: entries.jsonl (source of truth) + log.md (rendered)
├── pre/              ← PRE-strategy signal-edge gate
│   ├── signal_edge.py    E-Ratio (MFE/MAE asymmetry) + permutation test + baseline
│   ├── signals/          signal generators (emit +1/-1/0 series) + helpers
│   ├── scripts/          runnable edge reports (write to pre/artifacts/)
│   └── artifacts/        signal-edge JSON outputs
├── post/             ← POST-backtest validation
│   └── dsr.py            Deflated Sharpe Ratio (consumes harness returns + trial_count)
├── tests/
├── calibration_results.md
└── README.md
```

Why the split: it keeps the two halves of the pipeline from blurring together,
and gives `dsr.py` **one unambiguous home** — `research.post.dsr` is *the*
canonical DSR for this repo. See "DSR canonicality" below.

## End-to-end pipeline

```
  register_hypothesis()            research.log        ← log the idea + edge_gate_role
        │
        ▼
  pre/signal_edge gate             research.pre        ← E-Ratio on the raw entry
        │                                                 (HARD GATE for breakout/
        │                                                  continuation; DIAGNOSTIC
        │                                                  only for pullback/MR)
        ▼
  qhf walk-forward harness         ../qhf_harness      ← full backtest, OOS folds,
        │  (separate repo)                                Pepperstone Razor costs
        ▼
  post/dsr verdict                 research.post       ← Deflated Sharpe vs the
        │                                                 selection-inflated benchmark
        ▼
  update_hypothesis() / log_dsr_evaluation()           ← record the result back
```

`research.log.trial_count()` is the honest floor N that feeds the DSR haircut, so
the whole loop closes: more logged trials → larger N → a harder DSR gate.

## DSR canonicality (avoiding divergence)

There are two DSR implementations, by necessity:

| Implementation | Repo | Role |
|---|---|---|
| `research.post.dsr` | this repo | **Canonical.** Wired to `research.log.trial_count()`. |
| `qhf/metrics/deflated.py` | `../qhf_harness` (separate repo/venv) | Harness-side twin, so the backtester can deflate inline without importing this package. |

They must stay numerically identical. The contract is locked by
`tests/test_dsr_parity.py` — golden vectors for the deterministic primitives
`psr()` and `expected_max_sharpe()`. **qhf's `deflated.py` must reproduce these
same values:**

| Primitive | Inputs | Expected |
|---|---|---|
| `psr` | `(0.05, 0.00, 500, 0.0, 3.0)` | `0.8678355793218056` |
| `psr` | `(0.08, 0.02, 1000, -0.5, 6.0)` | `0.968021483091013` |
| `psr` | `(0.03, 0.01, 250, 0.4, 9.0)` | `0.6244603832213759` |
| `expected_max_sharpe` | `(10, 0.001)` | `0.04979317033695131` |
| `expected_max_sharpe` | `(100, 0.001)` | `0.08002469001362901` |
| `expected_max_sharpe` | `(1000, 0.0025)` | `0.16275607554588317` |

If the math changes, change it in both repos and bump these vectors deliberately.

## Conventions

- **`pre/` is a gate, not a veto for everything.** E-Ratio is a HARD GATE for
  breakout/continuation entries and a DIAGNOSTIC ONLY for pullback/mean-reversion
  entries (whose edge legitimately lives in the exit). Set `edge_gate_role` at
  registration so the rule travels with the hypothesis.
- **`post/` takes per-observation returns only.** Annualisation in `DSRResult`
  is display-only and never enters the math.
- **Never hand-edit `log/log.md` or `log/entries.jsonl`.** The JSONL is
  append-only and hash-chained; `log.md` is regenerated by `render_markdown()`.
  Historical `artifact_path` values in the log point at wherever an artifact was
  written *at run time* — they are immutable records, not live paths.

## Running

```bash
research/.venv/bin/python -m pytest research/tests        # full suite
research/.venv/bin/python -m research.seed_log            # inspect log (dry-run; --commit to write)
research/.venv/bin/python -m research.pre.scripts.run_zlch_edge   # an edge report
```
